# General Chat and Video Studio Foundation Design

## Objective

Add two first-class Orca surfaces:

- General Chat, a project-independent conversation experience backed by Orca's existing native structured-agent chat.
- Video Studio, a durable project and workflow surface that can later dispatch HyperFrames and Remotion workers.

This phase establishes navigation, ownership, persistence, and usable UI. It does not implement web search, Deep Research, or video rendering.

## Scope

### Included

- `general-chat` and `video-studio` top-level views in the App Rail and application view history.
- General Chat conversation creation, recent-conversation navigation, model/provider selection, attachments, streaming transcripts, and existing native-chat session controls.
- A hidden application workspace per execution host so chat sessions have a valid runtime workspace without belonging to a user project.
- Video Studio project creation, selection, editing, deletion, and workflow-stage tracking.
- Responsive desktop, web, and mobile-web layouts using the existing Orca design system.
- Explicit unavailable and recovery states for hosts, providers, application-workspace creation, and corrupt Video Studio storage.

### Excluded

- Web search and Deep Research execution.
- Plugin-specific chat tools beyond capabilities already exposed by native chat.
- HyperFrames or Remotion installation, job dispatch, preview, and rendering.
- New AI-provider integrations.
- A second transcript or message persistence system.

## Product Behavior

### Navigation

General Chat and Video Studio appear as App Rail destinations after Workspaces and before the existing task-oriented destinations. They use the rail's existing overflow behavior, keyboard roving focus, tooltips, and active-page semantics.

Opening either destination records a top-level view visit and preserves the existing return target. Returning to Workspaces restores the previously active workspace and tab. Both destinations remain addressable when no project has been added.

### General Chat

The General Chat surface contains:

- A conversation list with a New chat action and native session titles.
- A main transcript using the existing native-chat message, reasoning, tool, attachment, and composer components.
- Existing provider, model, and permission controls where supported by the selected host.
- An empty state that explains General Chat is independent of projects.
- An explicit host selector when more than one execution host is available.

Creating a conversation ensures the selected host's application workspace exists, then creates a normal structured-agent session owned by that workspace. Switching conversations changes only the selected session; it does not create or activate a user-visible worktree.

General Chat never silently changes execution hosts. If a saved host is unavailable, the surface keeps the intended host visible and offers retry or explicit host selection.

### Application Workspace

Each execution host can own one internal folder workspace with these semantics:

- It uses the host's Orca application-data area rather than a repository or user project.
- It has a stable identity derived from the host identity, not from a platform-specific absolute path.
- It is marked with an internal `general-chat` purpose and excluded from project, workspace, source-control, and cleanup UI intended for user workspaces.
- It remains a real runtime workspace so existing structured-session creation, transcripts, attachments, tools, sleep, recovery, and remote transport continue to work.
- Creation is idempotent and safe when two windows request it concurrently.
- Removal or corruption is recoverable by ensuring it again; conversation journals remain governed by native-chat retention.

Local, SSH, and paired runtime hosts resolve their own application-data paths. Renderer code never constructs remote paths or assumes Windows separators.

### Video Studio

Video Studio contains a project list and a project detail surface. A project has the following durable fields:

```ts
type VideoStudioProject = {
  id: string
  title: string
  prompt: string
  aspectRatio: '16:9' | '9:16' | '1:1'
  durationSeconds: number
  workflowStage: 'research' | 'script' | 'production'
  createdAt: number
  updatedAt: number
}
```

Titles are required after trimming. Duration is an integer from 5 through 3600 seconds. Project identifiers are generated by the host and are never inferred from titles. Updating a project advances `updatedAt` without changing `createdAt`.

The detail surface presents the three workflow stages and allows the user to update project metadata and stage. It does not expose fake render controls. The Production stage explains that a render engine will be connected in a later milestone.

Video Studio data is stored through a main-process persistence boundary with atomic replacement and schema validation. Renderer local storage is not the source of truth. Unknown future fields are tolerated, while invalid records are isolated and reported instead of causing the whole catalog to be discarded.

## Architecture

### Top-Level Views

Extend `TopLevelView`, UI view history, App Rail destination definitions, page mounting, sidebar visibility decisions, and navigation persistence with `general-chat` and `video-studio`. Each view receives dedicated open and close actions following the established Tasks, Artifacts, and Automations patterns.

### General Chat Boundary

Add a focused General Chat feature directory that owns page composition, conversation selection, and application-workspace acquisition. It consumes existing native-chat session catalogs and `NativeChatView`; it does not fork message rendering or composer behavior.

Application-workspace acquisition is exposed through the runtime API as an idempotent ensure operation returning a runtime workspace identity. Host-side code resolves paths, creates directories, serializes concurrent ensures, and applies the internal-purpose metadata. Renderer state stores only the selected host and conversation identifiers.

### Video Studio Boundary

Add a Video Studio feature directory for page composition and forms, plus shared request/result contracts and a main-process catalog service. The catalog service owns validation, atomic persistence, and CRUD operations. Renderer state keeps selection and edit drafts only.

The catalog contract is intentionally independent of HyperFrames and Remotion. A later render milestone can add job and output entities without changing the project identity or basic metadata contract.

## Data Flow

### New General Chat Conversation

1. The user selects New chat.
2. The renderer resolves the explicit or saved execution host.
3. The runtime ensure call returns that host's application workspace.
4. Existing structured-session creation starts the chosen provider in the returned workspace.
5. Native session publication adds the conversation to the recent list.
6. The page selects and renders the session through `NativeChatView`.

If steps 3 or 4 fail, no placeholder conversation is persisted. The page retains the chosen host/provider and exposes retry.

### Video Studio Project Mutation

1. The renderer validates immediate form affordances and submits a typed mutation.
2. The main process validates the full record and applies the mutation to the in-memory catalog.
3. The catalog is atomically written before success is returned.
4. The renderer replaces its catalog snapshot and selection from the returned result.

Failed persistence leaves the previously durable catalog authoritative and displays an inline error. Destructive deletion uses the existing confirmation-dialog pattern.

## User Interface

All components use tokens from `main.css`, primitives under `components/ui`, Lucide icons, Geist typography, the documented chat type scale, and existing scrollbar classes. No new palette, shadow tier, or arbitrary font size is introduced.

Desktop uses a compact list-and-detail layout. Narrow layouts collapse the list into a single surface with a predictable back action. Controls remain keyboard accessible, icon-only buttons receive accessible labels and tooltips, and focus returns to the invoking control after dialogs close.

The General Chat transcript remains visually quiet and uses native-chat foreground and focus tokens. Video Studio uses ordinary application `background`, `card`, `muted`, `border`, and `ring` roles rather than chat-only tokens.

## Failure and Recovery

- No host: show setup guidance and host management entry points.
- Saved host unavailable: retain host identity, show unavailable state, and require an explicit replacement.
- Provider unavailable: reuse native-chat provider availability guidance.
- Application workspace ensure failure: show the host-reported message with retry; do not fall back to another host or a user project.
- Video Studio catalog unreadable: preserve the file, isolate invalid records where possible, and return a recovery report.
- Video Studio write failure: keep the last durable snapshot and report that the requested mutation was not saved.
- Unsupported remote capability: identify the selected host and missing capability rather than hiding the destination.

## Cross-Platform and Remote Requirements

- Host-side path services choose Windows, macOS, Linux, SSH, and paired-runtime storage locations.
- No renderer path concatenation, drive-letter assumption, or shell-specific command is permitted.
- Folder workspaces and non-Git hosts are supported; Git metadata is never required.
- Application workspaces are excluded from user workspace cleanup by purpose metadata, not path matching.
- Mobile and web clients can browse existing conversations and Video Studio projects; host-dependent mutations report capability availability through the existing runtime transport.

## Verification

Repository rules prohibit low-value unit tests for UI wiring. Verification therefore consists of:

- Focused invariant tests for application-workspace identity/idempotency and Video Studio validation/atomic catalog behavior.
- Existing targeted typecheck, formatter, and linter commands while iterating.
- Presentational fixtures for General Chat empty/error states and Video Studio list/detail states.
- Electron validation with `ORCA_BACKGROUND_LAUNCH=1`, an explicit viewport and deterministic fixture state, inspected through Playwright CDP screenshots without showing or focusing native windows.
- One final `pnpm check:changed` gate after all edits.

5. Cross-surface handoff from research and chat into Video Studio projects.
